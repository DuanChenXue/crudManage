## 关键决策：jQuery + 自绘 UI

原 PRD 第 8 节写的是 Express + jQuery + Bootstrap。实际实现如下，**接口路径、响应体格式、数据模型、业务约束、页面结构全部与 PRD 一致**，只换实现载体：

| 层 | PRD 原方案 | 实际实现 | 原因 |
| --- | --- | --- | --- |
| 后端框架 | Express | `node:http`（内置） | 不引用三方库 |
| SQLite 驱动 | `better-sqlite3` | `node:sqlite`（内置） | 同上 |
| 前端 DOM | jQuery | **jQuery 3.7.1**（保留） | 需求明确要求 |
| 前端 UI | Bootstrap | 自绘 CSS/JS | 属三方 UI 组件库，与约束冲突 |

**依赖边界判定**：约束针对的是「三方 **组件库**」（提供现成 UI 组件与视觉规范的库）。jQuery 是 DOM 工具库，不提供 UI 组件，因此可以引入；Bootstrap 是 UI 组件库，不引入。

**jQuery 以本地文件引入**（`public/vendor/jquery-3.7.1.min.js`，87 KB，MIT 许可，SHA256 `fc9a93dd…f0b1a`），不走 CDN、不写进 `package.json`，因此同时满足：内网离线可用 + `npm install` 零依赖。

**表单控件不需要 Bootstrap 的组件**：本项目只用到原生 `<input>` / `<select>` / `<textarea>`，校验提示用就地 `.err` 元素，浮层用自绘 `.mask` + `.modal`。Bootstrap 提供的换行、输入组、校验态等能力均可用约 20 行 CSS 等价实现，引入会为 5 个表单字段付出 200+ KB 的体积。

收益：`package.json` 零依赖声明，克隆即跑。代价：需 Node.js ≥ 22.5.0。

## 验收结果

`npm test` = 前端静态校验（29 项）+ 后端隔离验收（38 项），**共 67 项断言全部通过**。后端验收重点覆盖：

- 空库启动不报错，列表返回空状态而非空白页
- 工号自动生成：空库首条 `EMP0001`，`EMP0009` 后新增得 `EMP0010`
- **已删工号不复用**：删掉 `EMP0026` 后新增得 `EMP0027`（序号存独立计数表，不从 `MAX(emp_no)` 现算）
- 并发新增 12 条无重号（序号生成与插入在同一 `BEGIN IMMEDIATE` 事务内）
- 前后端双重校验：绕过前端直调接口，非法手机号 / 非法部门 / 超长字段同样被 400 拒绝
- 手机号重复 → 409「该手机号已存在」，表单保持打开且已填内容不丢失
- 离职后禁止编辑：界面按钮置灰 + 提示，直接调 `PUT` 同样返回 400 且库中数据不变
- 离职员工仍可删除
- 部门 AND 状态组合筛选、关键词匹配姓名/工号/手机号、空结果
- 末页被删空且非第 1 页时自动回到上一页
- `emp_no` / `phone` 的 UNIQUE 索引在数据库层真实存在

浏览器端另外验证了完整交互链路（新增 → Toast → 列表首行出现；编辑回填 → 保存 → 原地刷新；删除取消不发请求 / 确认后移除；离职行编辑按钮置灰且点击无响应、删除按钮仍可用）。

## 期间修掉的一个真实缺陷

CSS 中 `.mask` 和 `.pager` 使用 `display: flex`，会覆盖 HTML `hidden` 属性默认的 `display: none`，导致弹层遮罩常显、按钮被挡住点不动。已在样式顶部加 `[hidden] { display: none !important; }` 修复并回归验证。

## 需要注意 / 待确认

1. **Node 版本要求**：`node:sqlite` 需 Node ≥ 22.5.0，且会打印 `ExperimentalWarning`（不影响使用）。如需消除，可用 `node --no-warnings server.js`。
2. **PRD Q7 未决**：离职目前是**不可逆终态**，误操作后只能人工改库。若产品确认需要「撤销离职」，需按 P2 的 R-13 拆出独立接口 `PATCH /api/employees/:id/status`。
3. **PRD Q8 未决**：工号前缀固定为 `EMP`。若公司已有既编号体系，现在改成本最低。
4. 未做：登录权限、Excel 导入导出、操作日志界面、移动端适配——均属 PRD 明确的非目标。`access_log` 表已在记录，可直接用 SQL 聚合。
5. **jQuery 升级方式**：为本地静态文件，升级需手动替换 `public/vendor/` 下文件并同步更新 `index.html` 的引用路径与 README 中的 SHA256。
